# SGLang validation on October 10, 2026

Giraffe connects to SGLang through its existing OpenAI Chat Completions client.
The only runtime-specific additions are read-only `/get_server_info` discovery,
explicit Prometheus metric mappings, and the corresponding CLI/UI configuration.
No inference adapter, dependency, fixture or scoring change was required.

## Setup

Apple M1, macOS 15.5, 8 GB RAM, Python 3.12.14. SGLang was installed from official
source commit `44bc478863052efdc455b0282b49830f68fdefb3` using the `srt_mps` extra
in `pyproject_other.toml`, in a separate virtual environment. The installed source
build reports `0.0.0.dev1+g44bc47886.d20261010`; this is not a tagged release.
PyTorch 2.13.0, MLX 0.32.3, mlx-lm 0.32.0 and XGrammar 0.2.7 were used.

The existing local `mlx-community/Llama-3.2-1B-Instruct-4bit` checkpoint was reused
without a model download (revision `08231374eeacb049a0eade7922910865b8fce912`).
Ollama and its installed models were preserved; its daemon was initially running
with no model loaded. The MLX backend uses its own local checkpoint, not Ollama.

SGLang serves `llama3.2-1b` on `127.0.0.1:30000/v1`. Settings: context 1,024,
total KV slots 2,048, maximum running requests 2, prefill chunks 64, static memory
fraction 0.30, MLX buffer-cache limit 0.125 GiB, CUDA graphs disabled, metrics enabled,
MLX sampling enabled, `llama3` tool parser and `xgrammar` grammar backend.
The server log confirms `MlxModelRunner`; the reported MPS device alone does not.

An external supervisor samples macOS memory pressure every 250 ms and stops only
the task-owned SGLang process group at critical pressure. The final server and full
run started at normal pressure; the full log contains normal and warning samples,
with no critical sample. The first attempt also never reached critical.
These observations qualify this run only.

## Results

Before the main update, all **316 automated tests passed** (307 existing plus nine
SGLang contract cases). The rebase validation is recorded separately below.
Ruff, JavaScript syntax and `git diff --check` pass. Tests cover explicit profile
selection, gauge/counter units, safe discovery, provenance, conflicting configuration,
malformed metadata and secret exclusion. The final source fingerprint matches the
code used for the live run.

The connection/serving/correctness smoke run passed with 13 requests. A separate
nonstreaming run passed access, serving, correctness, JSON and automatic tool
calling with 20 requests.

The final full run selected all 19 checks, including every expanded workload and
optional JSON/GPU checks: **558 requests, 6 checks passed, 2 failed, 11 inconclusive**.
There was no run abort or server crash. All 155 serving telemetry scrapes succeeded.
556 requests completed; one client cancellation and one client deadline were
intentional. Traffic ceilings were 800 requests, 1,800 seconds, concurrency 2,
120 seconds/request and 128 output tokens. Samples were 6 and sustained traffic 30
seconds. Acceptance limits were retained from the existing local validation setup.

Automatic complete and streamed calls both returned `get_weather` with
`{"city":"Delhi"}`. Forced diagnostics completed but returned `{}` arguments,
failing their diagnostic answer checks. Giraffe intentionally reports forced
diagnostics separately from automatic capability; a passing tools check does not
claim those diagnostics passed. No tool was executed.

The first full attempt crashed in llguidance's CPU grammar-mask compilation because
the bundled Python/Inductor extension could not load `@rpath/libc++.1.dylib`.
Disabling compilation exposed a separate startup import failure. Using SGLang's
default XGrammar CPU mask removed the crash, verified with both forced request
formats and the complete rerun. No SGLang package source was patched.

These results verify integration, not an all-passing deployment. The exact-answer
failures, forced diagnostic failures and missing timing/GPU evidence remain visible.
Linux/CUDA SGLang and other models were not live-tested here. Full reports, tested
configurations, launch helper, source fingerprints, logs and memory samples remain
in the surrounding workspace's `artifacts/sglang-trial` directory.

## Follow-up diagnosis

Direct HTTP requests, bypassing Giraffe's inference client and scorer, reproduced
the fixed/live session mismatches in both streaming and nonstreaming formats.
Reconstructed streaming request hashes and conversation-history hashes match the
original full report. Fixed history contains `Golden Crust`; the endpoint returns
`Golden Crust Bakery`. Live history contains `"Flour & Co."`; the endpoint returns
`Flour & Co`. The live case preserves the name but violates exact repetition through
formatting differences; it is not evidence that conversation history was lost.
Exact scoring intentionally preserves case and punctuation and normalizes whitespace.

The direct stop request returns `Blue ` with `finish_reason: stop` and
`matched_stop: [END]`. Stop handling worked in this reproduction. The failed fixture
also requires copying lowercase `blue` exactly; describing this as a broken stop
implementation would conflate model instruction following with API stop behavior.
The fixture and scorer predate the SGLang changes and were left unchanged.

The original 150.938 ms generator lag exceeds the 100 ms qualification threshold
(warm first-output median 54.385 ms). Giraffe uses the maximum client event-loop
delay across the run to qualify timing checks, so one pause can affect multiple
workloads. This is an existing conservative qualification rule, not proof of an
endpoint performance violation. No timing violation lists were reported in the
original inconclusive checks.

Two bounded diagnostic runs retained the original acceptance limits and exercised
first output, generation, capacity, fairness and recovery, with six seconds of
sustained traffic and asyncio slow-callback logging enabled:

| Diagnostic | Real requests | Maximum generator lag | Five core timing verdicts |
| --- | ---: | ---: | --- |
| Metrics enabled | 99 | 62.780 ms | All pass |
| Metrics disabled | 89 | 100.293 ms | All inconclusive |

These are focused diagnostics, not replacements for the full 558-request result.
Debug logging perturbs timing. The original pause's cause remains unproven; the
metrics mapping is not necessary for a threshold crossing. No inference, fixture,
scoring or timing code was changed during this diagnosis.

The raw metrics contain no DCGM series. Giraffe currently maps NVIDIA DCGM health
metrics, so Apple GPU health is unverified. Runtime weight/cache memory gauges do
not supply the complete GPU-health contract. Raw requests, metrics and diagnostic
reports are saved under `artifacts/sglang-trial/diagnosis` in the surrounding workspace.
